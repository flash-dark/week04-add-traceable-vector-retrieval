## 1. 切片与双库

- [ ] 1.1 为材料正文增加切分，默认自动窗口约 800 字、重叠约 80 字，并保留材料使用的切分策略
  verify: 一份短于窗口的材料得到一个切片；超过窗口时在空行、换行或句号处断开，并记录起止偏移
- [ ] 1.2 把切片正文写入 `knowledge_chunks`，字段至少包含材料标识、`class_id`、`chunk_index`、`start_offset`、`end_offset`、`chunk_text`
  verify: 主键可被后续向量写入引用
- [ ] 1.3 将每个切片嵌入后写入向量数据库，主键与 payload.`chunk_id` 都等于 `knowledge_chunks.id`，向量库不作为正文来源
  verify: 任取一个切片，三处编号相同，且用该编号能取回 MySQL 中的原文

## 2. 本班检索

- [ ] 2.1 检索前只保留会话中的 `class_id`，忽略请求里自行提交的班级和角色
  verify: 同一问句分别从 A 班和 B 班会话发起，结果集互不包含对方切片
- [ ] 2.2 实现关键字检索：只查本班全文索引，不调用嵌入
  verify: 原文中的词可以命中；请求期间没有嵌入调用
- [ ] 2.3 实现向量检索：问句嵌入后计算余弦，丢弃低于 0.35 的切片
  verify: 构造一条相似度低于 0.35 的切片，确认它不出现
- [ ] 2.4 实现混合检索：按 RRF `1/(60+名次)` 融合两路名次，默认使用该模式
  verify: 两路都命中的切片排在只命中一路的切片之前；两路皆空时结果为空

## 3. 出处与问答

- [ ] 3.1 每条命中返回材料标识、标题、切片序号、起止偏移和切片正文
  verify: 用返回的材料标识和偏移能在入库正文中截出同一段文字
- [ ] 3.2 问答对当前这句话做本班混合检索并只取前 4 条；有切片时才把标题、序号和正文交给生成过程，回答中的 `[1]`、`[2]` 与列表顺序一致
  verify: 命中两条时，回答引用与出处列表的第 1、第 2 条对应
- [ ] 3.3 无候选切片时返回「资料中未找到相关内容」，`citations` 为空，且不调用生成模型
  verify: 用材料中不存在的问题请求问答，确认没有对话网关访问，响应中没有出处
